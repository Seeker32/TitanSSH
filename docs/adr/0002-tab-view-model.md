# ADR-0002: 标签视图模型 — 终端标签为会话锚点

- 状态：已接受（2026-08-21）
- 关联：#36、ADR-0001

## 背景

架构规定 "Session ≠ UI: tab = view only"、数据模型包含 TerminalTab，但现状从未兑现：标签栏直接渲染会话列表，`activeView` 就是 sessionId——标签即会话，标签栏无法承载任何非终端视图。进程监控需要第二种标签类型（全量进程列表），没有现成落点。

可选方案：

1. Modal 逃生舱：点击 top-5 面板弹全屏 Modal 展示进程表。零导航机制改动，但"标签页"是假的，下次新增视图类型（日志、搜索等）时这笔债仍要还。
2. 引入真正的标签视图模型：TerminalTab 视图实体，标签栏可承载多种标签类型。

## 决策

采用方案 2，并把生命周期语义定死：

- **终端标签 = 会话锚点**：一个 Runtime Session 恰有一个终端标签；关闭终端标签即触发 close_session 完整 teardown（终端、SFTP、主机监控、进程监控、共享采样连接）。这与现状"关 tab 即断连"的用户行为完全一致——本 ADR 只是把责任归属写清楚：标签发命令，连接生命周期归 SessionManager。
- **进程标签 = 纯视图**：引用会话但不拥有连接；随时打开/关闭，不触发采样启停（采样跟随会话生命周期）；重开时立即渲染缓存的最新进程快照。
- "Tab never owns the connection" 由锚点机制兑现：任何标签都不拥有连接，只是终端标签承担锚点职责。
- 本次**不**实现"会话脱离标签存活"（会话恢复、后台保活 UI）——留待出现真实需求再议。

## 后果

- 这是本项目迄今最大的前端重构：session store 语义、标签栏渲染源、主页布局全要动，`activeView` 的语义（会话视图 → 标签视图）需要迁移。
- 后续新增视图类型有现成机制可挂，架构债就此偿还。
- 关闭终端标签的用户可见行为不变（无回归），新增的是"进程标签可独立开关"。
